Sequence adjustment: milestone 1 establishes pure authorization and evidence contracts early; these are reused in milestones 5 and 14 and do not claim those milestones complete. Safety design starts now, but no generated medical answer is enabled before milestone 9. Complete milestones 1 and its tests in the initial implementation change; do not rush into external infrastructure provisioning.

Failure contract: unauthorized/expired requests disclose no patient data; revoked access checked against authoritative membership each request. Unavailable DB means record unavailable, not absent facts. Provider errors return an honest temporary failure, never simulated medical answers. Unknown threshold remains unknown. Concurrent changes return conflict, never last-write-wins. Incomplete migrations fail readiness. Storage/extraction errors leave documents pending/failed and no confirmed facts. Emergency escalation cannot depend on model availability or a successful database call.

Operational deliverables before staging: documented environment variable names and secret ownership, local/test/staging/production separation, migrations and synthetic seeds, clean build/deploy commands, versioned health checks, redacted telemetry and alert owner, separate database/object backup retention, measured restore procedure, backward-compatible rollback and incident stop procedure. Real patient data stays outside Git and automated tests.
